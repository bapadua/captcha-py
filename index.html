Manual do projeto

Resolvendo captchas distorcidos sem OCR genérico

captcha-am é uma API em Python/FastAPI que recebe a imagem de um captcha de texto (letras coloridas sobre ruído, cortadas por uma linha diagonal) e devolve o texto reconhecido — comparando cada caractere contra templates extraídos à mão, em vez de depender de reconhecimento genérico de fonte.

01 Visão geral

O captcha alvo tem letras azuis sobre um fundo com ruído na mesma cor, cortadas por uma linha diagonal escura. A primeira tentativa foi um OCR genérico (Tesseract) — acertou só 1 das 3 amostras conhecidas. O motivo: nessa fonte as letras às vezes se tocam sem nenhum "vale" de tinta entre elas, então qualquer abordagem que suponha fronteiras óbvias entre caracteres tende a errar a segmentação antes mesmo de tentar reconhecer.

A solução trocou OCR genérico por um classificador por caractere: cada pedaço candidato da imagem é comparado contra templates já conhecidos de cada letra, e a divisão em caracteres é escolhida junto com o reconhecimento — por programação dinâmica, testando onde cortar e escolhendo a combinação de cortes cujos pedaços mais se parecem com algum template, em vez de adivinhar a fronteira primeiro.

O código do OCR genérico continua em app/ocr.py / app/preprocessing.py como referência histórica, mas não é mais usado pela API.

02 Como funciona o pipeline

  1. 1

    Isolar por cor

    A máscara de glifos é extraída filtrando a cor específica das letras — a linha diagonal e o ruído de fundo, por terem outra tonalidade, ficam de fora do filtro.

  2. 2

    Limpar resíduos

    Pequenos resíduos que sobram do filtro de cor são removidos, deixando só os traços que de fato formam os caracteres.

  3. 3

    Segmentar + classificar (DP)

    Em vez de cortar primeiro e reconhecer depois, uma busca por programação dinâmica testa onde cortar a máscara e, para cada corte candidato, compara o pedaço contra os templates de cada caractere — escolhendo a divisão cujos pedaços mais se parecem com algo já conhecido.

03 Setup

Sem Tesseract instalado no sistema — só seria necessário para usar app/ocr.py diretamente.

Linux 
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/uvicorn app.main:app --reload
Windows 
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt
.venv\Scripts\uvicorn app.main:app --reload

04 API

GET/health

Checagem de disponibilidade.

POST/solve

Recebe a imagem (multipart/form-data, campo file) e um campo opcional length (quantidade de caracteres, padrão 4). Devolve {"text": "..."}. 

curl -F "file=@a.png" http://localhost:8000/solve
POST/mask-preview

Devolve a máscara isolada (a mesma usada por /solve e /templates por dentro) como PNG. Existe só para a UI de treinamento marcar cortes nas coordenadas certas.

POST/templates

Treinamento incremental: você já sabe o texto certo de um captcha e quer que o classificador aprenda com ele. Recebe file e text, devolve os caracteres adicionados.

Muda o estado do classificador para todo mundo que usa a API — não deixe exposto publicamente sem proteção.

05 Treinando com novas amostras

Três formas de ensinar o classificador a partir de um captcha cuja resposta certa você já sabe.

Em tempo real, via API

Só funciona com segurança se todo caractere de text já tiver pelo menos 1 template cadastrado. Se algum caractere for totalmente novo, a API recusa com HTTP 422 e pede os cortes manuais: 

curl -F "file=@novo.png" -F "text=ab3d" http://localhost:8000/templates

# com um caractere nunca visto, informe os cortes (coordenadas da máscara isolada)
curl -F "file=@novo.png" -F "text=ab3d" -F "cuts=90,180,270" http://localhost:8000/templates

Pela interface web

Com a API rodando, http://localhost:8000/ serve uma página simples (HTML/CSS/JS puro, sem framework) para fazer a mesma coisa sem montar curl à mão: arraste a imagem, cole um print ou escolha o arquivo, veja a máscara isolada e clique entre as letras para marcar os cortes — o campo cuts é preenchido automaticamente.

Essa página depende do backend rodando localmente; o GitHub Pages aqui serve só este manual estático.

Em lote, editando o código

Reconstrói app/templates.npz do zero a partir de app/known_samples.py — ao contrário do endpoint, que só adiciona: 

.venv/bin/python scripts/build_templates.py

06 Testes

.venv/bin/pytest tests/ -v

Os testes rodam o pipeline direto contra as 3 imagens de amostra (a.png, b.png, c.png) e comparam com o texto esperado.

07 Limitações conhecidas

O classificador acerta as 3 amostras disponíveis, mas isso testa contra as mesmas imagens de onde vieram os templates — não é validação contra captchas nunca vistos.

  • Tamanho do captcha: a API assume 4 caracteres por padrão (length=4); ajuste por requisição se variar.
  • Letras com um só exemplo: cada caractere aparece só 1 ou 2 vezes nos templates — letras parecidas entre si (ex.: m vs. n) tendem a ser confundidas até existirem mais exemplos rotulados, que é exatamente para isso que serve o POST /templates.
